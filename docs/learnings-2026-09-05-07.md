## 1. The meta-lesson: gates work — in both directions

The single most valuable engineering decision of the window was insisting
that **no analysis stage writes to the library without a measured agreement
number**. The number decides, not the vibes. (Gate numbers: fulltags-roadmap
§0.)

Why this matters more than it looks:

- The BPM failure is the interesting one. beat_this is ISMIR-2024 SOTA, and
  its output is _consistently, plausibly wrong_ — a locked ~2.2–2.6%
  beat-period offset vs rekordbox (130.43 vs 127.66-class pairs) on half
  the sample. No listener would notice one track drifting 2%; every
  sync/beatjump would. **A model can be wrong in a way that is invisible
  per-sample and systemic in aggregate.** Only a sampled-diff gate against
  independent ground truth catches that class.
- The genre saturation is the second flavor: a model can also be _nearly
  constant_ — statistically "confident" everywhere while discriminating
  nothing. Any gate that only checked accuracy-vs-truth on a held-out set
  might have missed it; the tell was the distribution, not the score.
- The pivot itself is a finding: **a failed write gate does not mean the
  analysis is worthless — it means the write target was wrong.** Beat
  arrays (the beats ledger in the archive DB) deliver the value without
  clobbering the field rekordbox owns. CrateDeck's
  `archive_grid_cross_check` then uses that ledger as an _independent
  second opinion_ on rekordbox's own grids (real-archive verdict: 46 ok /
  40 off / 2 octave) — which the verify pipeline could never produce,
  because its grid check compared an analysis against itself.

Corollary we now operate by: keep the gate as a hard rule — every future
analysis stage (structure, vocal density, similarity) gets a measured
agreement number recorded in the roadmap doc before anything touches files.

## 2. Model-output skepticism, generalized

The BPM phase-lock joins the family of "the year is always 2023" errors:

1. **flash-lite guesses 2023** for every release year (fixed by SC
   `display_date` verification).
2. **beat_this phase-locks 2.2–2.6% off** (fixed by refusing the tag write,
   keeping the grid as data).
3. **the effnet genre head saturates** (fixed by deferring the write).

The general law: _a model's most dangerous failure mode is not garbage
output — it is confident, uniform, subtly-wrong output that no single
instance raises an eyebrow at._ Defenses that held up this window:

- Ground-truth reads from files, never from our own DB (the audit
  principle).
- Sampled-diff review before any batch (the 24-track BPM sample cost an
  hour and saved 24 wrong tags; the full-library pass would have saved 88).
- Distribution checks, not just accuracy checks (saturation is a smell).
- Provenance stamps (`TXXX:AI-GENRE|0.92`) so AI-filled fields remain
  identifiable forever.
- A human-diff view of what a batch would change before it changes it.

And one more, learned the hard way: **saturated-constant model output is
never believable.** The mood pass shipped with the head label order
inverted — every track read dance=0.00/party=1.00 — and that uniformity,
not any accuracy metric, is what flagged it within minutes.

## 3. The archive is the highest-value test fixture we own

Three of the best bugs of the window surfaced only when the shipped code
ran against the real 88-track archive (full mechanics + fixes in the
roadmap's bug-audit log: WAV/AIFF stamp reads reading nothing, the
art-embedded `-map 0:a` miss, and the mood label-order inversion — see
[fulltags-roadmap.md](fulltags-roadmap.md) §5b). Every one passed the
synthetic test matrix. The meta-lesson: **the archive itself is the
highest-value test fixture we own.** Synthetic fixtures prove the code
does what we said; the real library proves what we said was the right
thing to say. Execution passes against production data are not a luxury
after tests — they are a different test.

## 4. Two quiet bugs worth remembering

- **`groundTruth` read TXXX:ENERGY as hardcoded null** — `readFullTag()
  .energy` always lied, and the audit "verified" nothing. A verifier that
  doesn't read the real source is decoration.
- **The TOCTOU enqueue re-check**: a mutating agent tool must re-check the
  interlock server-side at enqueue, not just client-side at prompt time —
  the state can change between the two.

## 5. Product learnings

- **Same size does not mean same content — the Sep 9 shelf sweep's big
  find.** The size-only merge classified 1,353 BANGERS files as "already
  archived"; the full-MD5 audit found **291 of them had different bytes**
  (in-place tag rewrites and early bitrot both produce this). Any
  "coverage" verdict built on size alone is a guess. Hence
  `megadj shelf-archive --deep`: MD5 every same-size pair, preserve
  divergent copies, and let dedupe be a later human decision.
- **Filter junk before diffing, or the diff lies.** 1,446 of the 1,449
  "missing" files in the first naive BANGERS diff were `._*` AppleDouble
  junk. On any macOS-written FAT/exFAT drive, `._*`, `.DS_Store`,
  fseventsd and Spotlight state are noise that will bury the signal.
- **The product's sharpest feature fell out of data we already collect.**
  The player-compat verdict (`works on: XZ ✓ / AZ ✗`) is a join of
  Pioneer's public matrix with measured dual-DB row counts — an hour of
  glue that rekordbox itself cannot answer. Look for more joins of
  "public knowledge × measured local truth".
- **The gate that failed made the product better.** Blocking TBPM writes
  forced the beats ledger, which enabled the independent grid
  cross-check, which is now one of the most interesting reads in
  CrateDeck. The roadmap's gate discipline didn't just prevent damage;
  it rerouted effort to a better target.
- **Ledgers beat tags for contested fields.** Tags are for what hardware
  reads (and only where formats allow); the DB ledger is for everything
  else — beats, mood mirrors, cues, fingerprints. The split is now
  explicit: TKEY/genre/year/energy live in files; beats/downbeats/
  phrase-cues live DB-side; mood lives in both (stamped + mirrored).
- **Agents are operators, not gimmicks** — but only because the surface
  makes safe operation _the default_: readonly handles physically can't
  corrupt state (`readonly: true` sqlite), mutating tools are flagged and
  interlocked, attribution (`jobs.origin`) makes every action
  answerable, and `deckctl prep` gives a headless loop a digest instead
  of a dashboard. The MCP surface is now the same product, 1:1, for
  humans and agents.
- **Weekly cadence beats dashboard glancing.** B17 automation (mount →
  light scan; weekly verify) plus O83 `deckctl prep` mean the tool comes
  to you. The dashboard's job is to be boring.

## 6. Process learnings

- **Docs drift behind code in hours, not weeks.** Both audit passes of the
  window were dominated by _shipped-status staleness_ — tools counted
  wrong across four docs, features listed as open the same day they
  shipped. The fix that held: counted-and-census-verified claims (grep
  the code for the number, don't remember it), and re-running the link
  checker after every edit. (It recurred anyway — see the tool-count
  drift note in product-state — which is itself the lesson.)
- **Claims need provenance in docs too.** "98 tests across 11 files"
  (verified — the original draft said 12, caught by re-running the
  census), not "94 tests" (remembered).
- **Fix-all rounds with regression tests** (GetDat r1–r3, FullTags
  5-bug, CrateDeck r1–r3) outperform ad-hoc fixes: 30+ bugs closed in the
  window, each with a test that pins it. The pattern: audit the
  subsystem, fix everything found, regression-test each, record the
  _class_ in AGENTS.md so the next agent inherits the scar tissue.
- **The cap rule held.** Ideas entered the backlog only when something
  shipped or left. Two items were struck outright (Engine DJ, Serato —
  principles violations), one deleted (affinity model), several shipped
  and closed. The parking lot stays navigable because leaving is real.
